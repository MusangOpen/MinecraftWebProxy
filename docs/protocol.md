# SOCKS5 协议细节

本项目只实现 SOCKS5 的 `CONNECT` 命令（RFC 1928），认证支持「无认证」和「用户名密码」（RFC 1929）。

## 1. 方法协商

客户端连上代理服务器后，第一件事是发送方法协商报文：

```
+----+----------+----------+
|VER | NMETHODS | METHODS  |
+----+----------+----------+
| 1  |    1     | 1..255   |
+----+----------+----------+
```

本项目的发送策略：

| 输入 | 实际发送的字节 | 含义 |
|---|---|---|
| 用户名和密码都为空 | `05 01 00` | 只支持「无认证」 |
| 用户名或密码非空 | `05 02 00 02` | 支持「无认证」和「用户名密码」 |

服务器从 METHODS 里挑一个回：

```
+----+--------+
|VER | METHOD |
+----+--------+
```

| 返回值 | 处理 |
|---|---|
| `0x00` | 无需认证，直接发 CONNECT |
| `0x02` | 需要用户名密码认证 |
| `0xFF` | 服务器不接受任何方法，报错断开 |
| 其它 | 报错断开（`[DEBUG] 代理服务器选择了不支持的认证方法`） |

## 2. 用户名密码认证（RFC 1929）

```
+----+------+----------+------+----------+
|VER | ULEN |  UNAME   | PLEN |  PASSWD  |
+----+------+----------+------+----------+
| 1  |  1   | 1..255   |  1   | 1..255   |
+----+------+----------+------+----------+
```

- `VER` 固定 `0x01`
- `ULEN` / `PLEN` 是字节长度（不是字符数）

服务器回：

```
+----+--------+
|VER | STATUS |
+----+--------+
```

`STATUS == 0x00` 表示认证通过，其它值失败。

## 3. CONNECT 请求

```
+----+-----+-------+------+----------+----------+
|VER | CMD |  RSV  | ATYP | DST.ADDR | DST.PORT |
+----+-----+-------+------+----------+----------+
| 1  |  1  | X'00' |  1   | Variable |    2     |
+----+-----+-------+------+----------+----------+
```

本项目**固定使用 ATYP = 0x03（域名）**：

```
05 01 00 03 <len> <host bytes> <port_hi> <port_lo>
```

即使目标是 `127.0.0.1` 这种纯 IP，也按域名发出去，由代理服务器自己解析。
好处是代理侧可以做 DNS 解析，避免本地污染；代价是要求代理服务器支持域名解析。

## 4. CONNECT 回复

```
+----+-----+-------+------+----------+----------+
|VER | REP |  RSV  | ATYP | BND.ADDR | BND.PORT |
+----+-----+-------+------+----------+----------+
```

`REP` 非 0 表示失败：

| REP | 含义 |
|---|---|
| `0x01` | 一般性失败 |
| `0x02` | 规则不允许 |
| `0x03` | 网络不可达 |
| `0x04` | 主机不可达 |
| `0x05` | 连接被拒绝 |
| `0x06` | TTL 过期 |
| `0x07` | 不支持的命令 |
| `0x08` | 不支持的地址类型 |

失败时仍需把 `BND.ADDR + BND.PORT` 读完再关闭，否则可能触发 RST。

`ATYP` 决定剩余长度：

| ATYP | BND.ADDR | 剩余总字节 |
|---|---|---|
| `0x01` | 4 字节 IPv4 | 6 |
| `0x03` | 1 字节长度 + 域名 | 1 + len + 2 |
| `0x04` | 16 字节 IPv6 | 18 |

## 5. 数据转发

CONNECT 成功后 socket 就是一条透明隧道，双方直接收发原始字节，不再有 SOCKS5 封装。
本项目按 4096 字节一块原样转发，不解析应用层协议。

## 6. 超时

`socket` 的 `SO_RCVTIMEO` / `SO_SNDTIMEO` 都设为 **10 秒**。

注意：这个超时是单次 `recv` / `send` 的阻塞上限，不是空闲超时。
Minecraft 长时间没数据包时，转发线程会在 10 秒后 `recv` 返回 -1 并断开连接。
